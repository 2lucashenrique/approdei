# Plan to Fix Refuel and Transaction Registration

The user reported that while trip registration is working, refuel and transaction registrations are not appearing. This is likely because these components are still generating temporary IDs or including `userId` / `id` fields that conflict with the Supabase auto-generation logic implemented in `useUserData.ts`.

## Technical Details

1.  **Refuel Registration Fix**:
    *   In `RefuelPage.tsx`, the `handleAddRefuel` function generates a temporary ID for the associated transaction (`refuel-${refuel.id}`).
    *   `RefuelPage.tsx` then calls `onAddRefuel(refuel)` and `onAddTransaction(transaction)`.
    *   In `Index.tsx`, `addRefuel` and `addTransaction` handlers are stripping `id` and `userId` correctly, but `handleAddRefuel` in `RefuelPage.tsx` is being passed the `refuel` object *before* it has a real database ID.
    *   The association between a refuel and its expense transaction currently relies on a client-side generated ID, which might be causing issues if the database expects the ID to be generated server-side or if the `Refuel` object passed to `onAddRefuel` still has an `id` field.

2.  **Transaction Registration Fix**:
    *   `AddTransactionPage.tsx` and `Index.tsx` handlers for transactions need to ensure they don't pass `id` or `userId` to the `addTransaction` mutation in `useUserData.ts`.

3.  **Data Flow Standardization**:
    *   Ensure all "Add" operations omit `id` and `userId` consistently across all pages (`NewTripPage`, `AddRefuelPage`, `AddTransactionPage`) and their parent handlers in `Index.tsx`.
    *   Verify that `useUserData.ts` mutations are correctly defined to handle the omission of these fields.

## Proposed Changes

### 1. `src/hooks/useUserData.ts`
*   Verify the `addRefuelMutation` and `addTransactionMutation` to ensure they don't try to insert `id` or `userId` if they are passed in the object (though they are typed to omit them, runtime objects might still have them).

### 2. `src/pages/RefuelPage.tsx`
*   Refactor `handleAddRefuel` to ensure the `Refuel` object passed to `onAddRefuel` doesn't have an `id` or `userId`.
*   Fix the transaction registration logic: since `Refuel` doesn't have an ID yet (it's generated by DB), we shouldn't try to link it with a custom ID string like `refuel-${refuel.id}` if that `refuel.id` is undefined or temporary.

### 3. `src/pages/Index.tsx`
*   Ensure the `addRefuel` and `addTransaction` wrappers strictly clean the objects before calling the mutations.

### 4. `src/pages/AddRefuelPage.tsx` & `src/pages/AddTransactionPage.tsx`
*   Remove any manual ID generation if present (already checked, but will double-check).
